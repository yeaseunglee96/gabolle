# GABOLLE 운영 지표 — 정의와 보는 곳 (S15P21E201-2010)

투자자가 먼저 보는 숫자(MAU 등)를 팀이 **같은 정의로, 매주 같은 자리에서** 보기 위한 문서다.
숫자를 계산하는 코드는 `backend/.../metrics/MetricsQueryService.java` 이고, **정의를 바꾸면 이 문서와 코드를 같이 바꾼다.**

## 보는 곳

| | |
|---|---|
| 화면 | 앱(웹) `/admin/metrics` — 운영자(ADMIN) 계정으로 로그인해야 열린다 |
| JSON | `GET /api/v1/admin/metrics?days=90` (최대 365) |
| CSV | `GET /api/v1/admin/metrics/daily.csv?days=90` — CSV(쉼표로 나눈 표. 엑셀·구글 시트에 바로 열린다) |

운영자는 배포 설정 `GABOLLE_ADMIN_EMAILS`(운영자로 삼을 이메일 목록)에 든 계정이다.

## 기본 규칙

- **날짜는 한국 날짜**(Asia/Seoul)다. 「오늘」은 아직 끝나지 않은 날이라 작게 나온다.
- **활성(active)** = 그날 로그인한 상태로 서버 API 를 1번 이상 부른 것. 앱을 열면 로그인 확인·홈 데이터 요청이 나가므로
  사실상 「앱을 연 날」이다. 푸시만 받고 열지 않은 날은 안 센다.
- 사람이 아닌 호출(내부 배치 등)은 세지 않는다.

## 지표

| 지표 | 정의 | 데이터 |
|---|---|---|
| DAU | 그날 활성인 서로 다른 회원 수 | `user_activity_day` |
| WAU | 그날 포함 7일 동안 1번 이상 활성인 서로 다른 회원 수 | 같음 |
| MAU | 그날 포함 30일 동안 1번 이상 활성인 서로 다른 회원 수 | 같음 |
| 비회원 DAU / MAU | 같은 기준을 익명 출입증(로그인 없이 쓰는 사람에게 주는 임시 번호)으로 센 수. **사람 수가 아니라 기기 수에 가깝다** — 앱을 지웠다 깔면 새 번호다. 회원 수와 더하지 않는다 | `anonymous_activity_day` |
| 신규 가입 | 그날 만들어진 계정 수(뒤에 탈퇴한 계정 포함) | `app_user.created_at` |
| 일정 생성 — AI | 그날 만든 여행 중 첫 일정이 추천(AI)으로 만들어진 것 | `trip` + `itinerary_versions` |
| 일정 생성 — 직접 짜기 | 첫 일정 판이 「AI 없이 직접 짜기」(`request_id = self_plan`)인 것 | 같음 |
| 일정 없음 | 여행만 만들고 일정이 아직 없는 것(추천 대기·중단) | 같음 |
| 코스 공유 글 | 그날 올라온 코스 공유 글(지운 글 포함) | `route_post.created_at` |
| 장소 제안 | 그날 들어온 장소 제안 | `place_suggestion.created_at` |
| 재방문율 D1 / D7 / D30 | 같은 날 가입한 사람들(코호트) 중 가입 **1·7·30일 뒤 바로 그날** 활성인 사람 ÷ 그 코호트 인원. 그날이 아직 다 지나지 않은 코호트는 빼고 계산한다 | `app_user` + `user_activity_day` |

## 🔴 언제부터 믿을 수 있나

활동일 기록(`user_activity_day`)은 **이 기능이 배포된 날부터** 요청마다 남는다(`source = REQUEST`).
그 전 날짜는 이미 있던 기록으로 **거꾸로 채웠다**(`source = BACKFILL`).

거꾸로 채운 근거: 가입, 로그인(`auth_session`), 토큰 갱신(`auth_refresh_token` — 앱을 다시 열 때 자주 생긴다),
여행·일정 만들기·고치기, 코스 글, 장소 제안. 비회원은 출입증의 처음·마지막 사용일만 있다.

그래서 **배포 이전의 DAU·MAU·재방문율은 실제보다 작다**(토큰 갱신 없이 앱만 연 날이 빠진다).
화면과 JSON 의 `notes.requestTrackingSince` 가 정확한 기록이 시작된 날이다. 그 날로부터 30일이 지나야 MAU 가 온전해진다.

신규 가입·일정 생성·코스 글·장소 제안은 원래 기록이라 처음부터 정확하다.

## 개인정보

남기는 것은 (회원 번호, 날짜) 한 쌍뿐이다. IP·기기·경로·시각은 남기지 않는다.
탈퇴하면 계정이 익명으로 바뀌므로 남은 활동일은 더 이상 사람을 가리키지 않는다 — 지난 MAU 가 탈퇴 때문에 줄지 않게 일부러 남긴다. 계정 행이 실제로 지워지면 활동일도 함께 지워진다(DB 의 `ON DELETE CASCADE`).

## 다운로드 수 — 아직 서버가 못 가져온다 (손으로 옮긴다)

| 스토어 | 지금 보는 곳 | API 로 가져오려면 |
|---|---|---|
| Google Play | Play Console → 통계 → 「설치된 사용자」/「사용자 획득」, 또는 「보고서 다운로드 → 통계」(월별 CSV) | 설치 수는 Play Developer Reporting API(오류·ANR 지표용)에 없다. 월별 통계 CSV 가 담긴 Cloud Storage 버킷(`pubsite_prod_…`)을 지금의 제출용 서비스 계정에 읽기 권한으로 열어 줘야 한다 — 콘솔 「사용자 및 권한」에서 사람이 한다 |
| App Store | App Store Connect → 앱 분석 → 「처음 다운로드 수」, 또는 판매 및 추세 | Sales and Trends 보고서 API(`/v1/salesReports`)는 지금 키로 부를 수 있지만 **공급업체 번호(vendor number)** 가 필요하다 — App Store Connect 「지급 및 재무 보고서」 화면 왼쪽 위에 있다 |

정해질 때까지: **매주 월요일**에 두 콘솔에서 지난주 다운로드를 읽어 팀 지표 시트의 「다운로드」 칸에 적는다.

## 아직 못 재는 것

- 다운로드 수(위) — 서버 밖 숫자다.
- 앱을 열었지만 서버 요청이 하나도 실패/차단된 날 — 활동으로 안 남는다.
- 회원과 비회원이 같은 사람인지 — 묶지 않는다(묶으려면 기기 식별이 필요한데 개인정보라 안 한다).
